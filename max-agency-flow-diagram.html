🤖 Max Agency

How an AI-powered team manages your software projects

📖 Important Terms (Read This First!)
PR (Pull Request)
A request to add new code to a project. Think of it as a "draft" that gets reviewed before final approval.
CI (Continuous Integration)
Automatic checks that run to make sure new code doesn't break anything. Like a quality test.
Issue
A task or problem tracked on GitHub. Each job the AI does is tracked as an issue.
Label
A tag attached to issues (like "assigned:claude-opus" or "phase:1") that helps organize and route work.
GitHub
A website where code is stored and teams collaborate. Max Agency uses it as the "bulletin board" for all work.
Merge / Auto-merge
When approved code is added to the final project. "Auto-merge" means the AI does it automatically without waiting for a human.
Branch
A separate copy of the code where changes are made before merging back to the main version. Like a draft workspace.
API Key
A secret password that allows the AI to access AI services. Like login credentials but for machines.
WSL (Windows Subsystem for Linux)
A tool that lets Windows run Linux commands. One of Max Agency's "brains" lives here.
Hermes
One of the AI agents (runs in WSL). Handles repetitive queue management and coding tasks.
Orchestrator
The manager AI. Decides which AI does what job and keeps everything moving.
CTO Review
Quality check by an AI expert before code is merged. Makes sure the code is good enough.

🔄 The Complete Workflow: From Task to Done

Step 1: Start a Project

You
Write a brief description of what you want built and paste a special prompt into Claude Desktop
→
Architect AI
Reads your brief, asks clarifying questions, creates a detailed PLAN.md with all tasks broken down
→
GitHub Issue Created
A "kickoff" issue is created with the plan attached

Step 2: Orchestrator Reads the Plan

Orchestrator AI (Hermes)
Every 5 minutes, reads the kickoff issue and PLAN.md. Creates one GitHub issue for each task in the plan. Labels them with who should do the work.
→
Issues Created
Issues labeled:
• "phase:0" (which phase)
• "assigned:claude-opus" (which AI)
• "backlog" (waiting status)

Step 3: Promote & Dispatch

Orchestrator Promotes
If a task has no dependencies (or all are done), moves it from "backlog" to "ready"
→
Orchestrator Dispatches
Changes label to "in-progress". The right AI (Hermes Coder or Claude Code) sees it and claims the issue

Step 4: AI Does the Work

Coder AI
Creates a branch
Makes code changes
Commits and pushes
Opens a PR (Pull Request)
→
GitHub PR Created
Shows all changes the AI made. Includes message "Closes #N" (links back to the original issue)

Step 5: Quality Review (CTO Review)

Orchestrator Creates CTO Issue
Creates a special issue asking the CTO AI to review the PR. Posts a link to the PR and acceptance criteria.
→
CTO AI Reviews
Reads the PR
Checks if CI (tests) pass
Posts a verdict: APPROVED or CHANGES REQUIRED

Step 6: Merge (Automatic or Manual)

APPROVED + HUMAN-REVIEW: NO
Orchestrator auto-merges the PR. Issue closes automatically. ✓ DONE
OR
APPROVED + HUMAN-REVIEW: YES
You get a Telegram message asking you to approve. Click approve and the Orchestrator merges. ✓ DONE
OR: CHANGES REQUIRED
The issue bounces back to "in-progress". The coder AI tries again with the feedback.

✨ What Makes Max Agency Smart

🤖 Automatic Routing
The right AI picks the right task. Complex planning goes to Claude Opus. Simple coding goes to Haiku. Quality review goes to CTO. You don't assign tasks — labels do it.
🔗 Smart Dependencies
The Orchestrator won't start task B until task A is done. You define dependencies in PLAN.md, and the pipeline respects them automatically.
✅ Quality Gates
Every PR gets reviewed by CTO AI before merge. Code tests (CI) are checked automatically. Bad code is caught before it gets merged.
📞 Human Loop
For risky changes, the AI asks YOU for approval via Telegram. You say yes or no. Full automation where safe, human oversight where needed.
♻️ Auto-Retry on Feedback
If CTO says "CHANGES REQUIRED", the issue bounces back to the coder. The coder reads the feedback and tries again. No human reminder needed.
📊 Always Visible
GitHub is the scoreboard. Check GitHub anytime to see which tasks are done, which are in progress, and which are waiting.

🎯 Your Job: What You Actually Do

1. Describe what you want: Write a brief. "I want an app that tracks my reading." That's it.

2. Answer 5 questions: The Architect AI asks clarifying questions. You answer them.

3. Approve the plan: You read the PLAN.md and say "yes, this looks good" or "please change X".

4. Check your phone: When something needs your eyes, Telegram pings you. You reply with "1 ✓" or "2 ✗".

5. Monitor progress: Optionally watch GitHub as issues close. But honestly, it mostly works by itself.

That's it. The AI handles the coding, reviewing, merging, and coordination.

🎩 The Magic: Why It Works

Three Ideas Make Max Agency Possible

1. GitHub is the Truth
Every AI reads GitHub issues and PRs to know what to do. GitHub is the single source of truth. If it's on GitHub, the AI knows about it.
2. Labels Route Work
Instead of a human assigning tasks, smart labels automatically tell the right AI to pick up the right task. "assigned:claude-opus" says "Claude Opus, this is for you".
3. The Orchestrator Conducts
A manager AI runs every 5 minutes. It promotes tasks, dispatches work, routes feedback, and auto-merges safe PRs. It's the conductor of the orchestra.
